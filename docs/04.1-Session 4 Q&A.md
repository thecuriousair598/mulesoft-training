# Session 4 Q&A: Errors and Logs

Things don't always go to plan, and this session was all about preparing for that. Building resilient, observable applications is what separates a good developer from a great one.

Let's review these crucial concepts.

---

### Questions for You:

1.  **Continue vs. Propagate:** What is the fundamental difference between the `On Error Continue` and `On Error Propagate` scopes? When would you choose to use one over the other?

2.  **HTTP Status Codes:** We returned a `400 Bad Request` for validation errors and a `500 Internal Server Error` for unexpected failures. Why is it so important to use specific HTTP status codes like these when communicating errors back to a client?

3.  **Correlation ID:** What is a `correlationId`? Why is it so important for logging in a system that might be handling hundreds of requests at the same time?

4.  **The `Try` Scope:** We wrapped our main processing logic inside a `Try` scope. What capability does this scope give us? What would happen if we didn't use it?

5.  **Structured Logging:** We configured our Logger to output a structured message with key-value pairs. How does this style of logging make it easier to monitor, search, and create alerts from log data compared to just logging plain text strings?
