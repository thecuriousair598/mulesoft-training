# Session 2 Q&A: Design a RAML

Great work on designing your first API with RAML! This session introduced a really important concept: designing your API before you build it. Let's dig into that idea.

---

### Questions for You:

1.  **Design-First:** What does it mean to take a "design-first" approach to building APIs? What do you see as the main advantages of working this way compared to just jumping in and coding?

2.  **RAML's Role:** What is RAML? What is its primary role in the API lifecycle?

3.  **APIKit Scaffolding:** APIKit automatically created "scaffolding" for our flows from the RAML file. What exactly did this scaffolding include? How did it save us time?

4.  **Example Responses:** In our RAML, we defined an "example" response. How is this useful during the development phase? How might it be useful for other developers who want to use your API?

5.  **Adding a New Endpoint:** If you were tasked with adding a new endpoint to your API, say `/goodbye`, what would be your very first step according to the design-first approach we learned in this session?
