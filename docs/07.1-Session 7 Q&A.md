# Session 7 Q&A: Mini-Project - The Orders API

Congratulations on completing the final project! You've successfully built a multi-endpoint API from scratch, combining almost all the skills you've learned throughout this course. This is a significant achievement.

Let's reflect on what you've built.

---

### Questions for You:

1.  **GET vs. POST:** Our Orders API had two HTTP "methods": `POST` to create a new order and `GET` to retrieve existing orders. Why are different HTTP methods used for different actions? What's the fundamental difference between these two?

2.  **File-Based Persistence:** We used a simple JSON file on the local disk to store our orders. What are some of the limitations or problems you might face with this approach if this were a real API used by many people at the same time?

3.  **201 vs. 200:** The `POST /orders` endpoint returned a `201 Created` status code, while the `GET /orders` endpoint returned a `200 OK`. Why the difference? What does `201 Created` signify to the client?

4.  **Putting It All Together:** This mini-project combined skills from all the previous sessions. Can you name at least three concepts from earlier sessions that you had to reuse or apply here? (e.g., RAML, DataWeave, error handling, etc.)

5.  **What's Next?:** If you were to continue working on this Orders API, what would be the next logical feature you would add? (e.g., updating an order, deleting an order, searching for a specific order by its ID, etc.) How would you go about implementing it?
